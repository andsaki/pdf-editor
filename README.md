# 請求書エディタ (Invoice Editor)

請求書の作成・編集を行い、PDFとしてダウンロードできるWebアプリケーションです。テキストや画像を自由な位置に配置して、カスタマイズ性の高い請求書を作成できます。

## 主な機能

- **請求書フォーム:** 宛先、請求元、品目（説明、金額）などを簡単に入力できます。
- **ライブPDFプレビュー:** 入力内容がリアルタイムでPDFプレビューに反映されます。
- **オブジェクトの自由な配置:**
    - **テキスト:** 好きなテキストを自由な位置に追加し、内容を編集できます。
    - **画像:** PCから画像をアップロードし、ドラッグ＆ドロップで位置やサイズを自由に変更できます。
- **プロパティ編集:** 追加したテキストや画像オブジェクトのX/Y座標や幅/高さを、フォームから数値で正確に指定できます。
- **PDF出力:**
    - **ダウンロード:** 完成した請求書をPDFファイルとしてダウンロードできます。
    - **別タブで表示:** PDFをブラウザの新しいタブで開き、すぐに確認できます。
- **状態プレビュー:** 開発やデバッグに便利な、現在のデータ状態をリアルタイムで表示する機能。

## 使い方

1.  **基本情報の入力:** 左側のフォームに「To」（宛先）、「From」（請求元）を入力します。
2.  **品目の追加:** 「Add Item」ボタンで品目を追加し、内容と金額を入力します。
3.  **テキストオブジェクトの追加:**
    - 「Add custom text」の入力欄にテキストを入れ、「Add Text」ボタンをクリックすると、プレビューに追加されます。
    - プレビュー上のテキストオブジェクトをクリックすると、青枠が表示され、編集モードになります。
    - 左側のフォームから、選択したテキストオブジェクトの内容やX/Y座標を編集できます。
4.  **画像オブジェクトの追加:**
    - 「Add Image」ボタンをクリックし、画像ファイルを選択します。
    - プレビュー上に追加された画像は、ドラッグして移動できます。
    - 画像の隅をドラッグすることで、サイズを変更できます。
    - 左側のフォームから、画像のX/Y座標や幅/高さを数値で正確に指定することも可能です。
5.  **PDFの出力:**
    - 「Open in New Tab」でブラウザ上でプレビューを確認します。
    - 「Download PDF」でPDFファイルを保存します。

## セットアップ

### 前提条件

- [Node.js](https://nodejs.org/) (v20.19.4 または `.nvmrc` で指定されたバージョン)
- [pnpm](https://pnpm.io/)

### インストール

1. リポジトリをクローンします:
   ```sh
   git clone https://github.com/andsaki/invoice-editor.git
   cd invoice-editor
   ```

2. pnpmを使って依存関係をインストールします:
   ```sh
   pnpm install
   ```

### 開発サーバーの起動

クライアントとサーバーの両方の開発サーバーを同時に起動するには、以下を実行します:

```sh
pnpm run dev
```

- クライアントは `http://localhost:5173` で利用可能になります。
- GraphQLサーバーは `http://localhost:4000/graphql` で利用可能になります。

## 非機能要件 (`react-pdf`)

`react-pdf`ライブラリを本アプリケーションで利用する上での、品質や制約に関する非機能要件を以下に定義します。

### 1. 性能 (Performance)

- **レンダリング速度:**
    - **プレビュー:** ユーザーの入力後、プレビュー用のPDF（Canvas）は500ミリ秒以内に再描画が完了すること。
    - **ダウンロード:** 100品目程度の請求書データから、最終的なPDFファイルを生成するのに3秒以上かからないこと。
- **メモリ使用量:**
    - 大量の画像やページを含むPDFをレンダリングする際に、ブラウザのメモリ使用量が過度に増加し、クラッシュを引き起こさないこと。目安として、単一のPDFプレビュー表示によるメモリ増加は200MB未満であること。
- **ファイルサイズ:**
    - 生成されるPDFのファイルサイズが、内容に対して不必要に大きくならないこと。テキスト中心の請求書であれば、100KB未満であることが望ましい。

### 2. ユーザビリティ (Usability / Developer Experience)

- **APIの直感性:**
    - Reactコンポーネントの知識があれば、JSXライクな宣言的UI（`<View>`, `<Text>`など）を用いて直感的にPDFのレイアウトを構築できること。
- **ドキュメントの充実:**
    - 一般的なユースケース（レイアウト、スタイリング、画像埋め込みなど）について、公式ドキュメントやサンプルコードが十分に提供されていること。
- **デバッグの容易さ:**
    - レンダリングエラーやレイアウトの問題が発生した際に、原因を特定しやすいエラーメッセージや警告が出力されること。

### 3. 互換性 (Compatibility)

- **ブラウザサポート:**
    - 主要なモダンブラウザ（Chrome, Firefox, Safari, Edge）の最新バージョンで、表示や機能が正常に動作すること。
- **既知の制約:** `react-pdf`の依存関係により、Safari 14.1未満の古いバージョンではPDFが描画されない問題が報告されています ([Issue #2020](https://github.com/wojtekmaj/react-pdf/issues/2020))。本プロジェクトのサポート対象はモダンブラウザの最新版ですが、制約として認識しておく必要があります。
- **Reactバージョン:**
    - React v18以降と互換性があり、Concurrent Modeなどの新機能と干渉しないこと。
- **PDF標準:**
    - 生成されるPDFが、PDF 1.7標準に準拠しており、主要なPDFビューワー（Adobe Acrobat Reader, 各ブラウザのビルトインビューワーなど）で正しく表示できること。

### 4. 信頼性 (Reliability)

- **安定性:**
    - 長時間アプリケーションを操作しても、ライブラリが原因でメモリリークや予期せぬクラッシュが発生しないこと。
- **エラーハンドリング:**
    - 不正なデータ（破損した画像、サポート外のフォントなど）が与えられた場合に、アプリケーション全体をクラッシュさせるのではなく、適切なエラーをスローまたはイベントハンドラを呼び出すこと。

### 5. セキュリティ (Security)

- **クロスサイトスクリプティング (XSS):**
    - 外部から与えられた文字列をPDFにレンダリングする際に、悪意のあるスクリプトが埋め込まれないように、適切にサニタイズまたはエスケープ処理が行われること。（注: `react-pdf`はCanvasに描画するため、HTMLベースのXSSリスクは低いが、データソースには注意が必要）
- **依存関係:**
    - ライブラリが依存するパッケージに、既知の脆弱性が存在しないこと。定期的な監査とアップデートが推奨される。
