# ADR: PDFプレビューと操作ライブラリの選定

## Context

### 意思決定の背景、及び目的

本アプリケーションの中核機能は、ユーザーが請求書PDFを編集し、その変更をリアルタイムでプレビューできる機能を提供することです。この機能を実現するためには、以下の要件を満たす必要がありました。

- Webアプリケーション内でPDFドキュメントを正確に表示できること。
- PDF上にテキスト、画像、テーブルなどのオブジェクトを追加、移動、サイズ変更、編集できること。
- ユーザーの編集内容に基づいて、最終的なPDFドキュメントを生成できること。

これらの要件を満たし、かつ開発の柔軟性とコスト効率を考慮したライブラリ選定が求められました。

### References

- `react-pdf`: https://react-pdf.org/
- `pdf-lib`: https://pdf-lib.js.org/

## Considered Options

- **Option A:** `react-pdf` (プレビュー) と `pdf-lib` (操作・生成) の組み合わせ
- **Option B:** `iframe`を使用したプレビュー
- **Option C:** プレビューと操作を一体で提供する単一ライブラリの採用（例: 商用ソリューション）

## Comparison Table

| Feature | Option A (`react-pdf` + `pdf-lib`) | Option B (`iframe`プレビュー) | Option C (単一ライブラリ) |
| :--- | :--- | :--- | :--- |
| **PDFプレビュー** | React上で柔軟に表示 | ブラウザの標準機能で表示 | ライブラリ依存 |
| **PDF操作・編集** | プレビュー上の操作と連動して、PDFの内部データを変更可能 | 不可 | ライブラリ依存 |
| **インタラクティブ性** | 高い（編集機能を自由に実装可能） | 低い | ライブラリ依存 |
| **柔軟性** | 高い（ライブラリの組み合わせ） | 低い | ライブラリ依存 |
| **コスト** | 無料 | 無料 | 商用の場合高コスト |
| **学習コスト** | 2つのAPIの学習が必要 | 容易 | 1つのAPI |

### Option A: `react-pdf` + `pdf-lib`

- **👍 Pros**
    - **役割分担:** `react-pdf`が「表示」、`pdf-lib`が「内部データの操作」と役割を分担することで、それぞれの得意分野を活かせる。
    - **高いカスタマイズ性:** `pdf-lib`を使うことで、PDFの内部構造に直接アクセスし、テキストや画像の位置、スタイルなどを細かく制御できる。
    - **オープンソース:** どちらも無料で利用できる。

- **👎 Cons**
    - **統合の複雑さ:** 「表示」と「内部データ」を扱う2つのライブラリを連携させるための開発が必要。
    - **座標の管理:** 画面上のプレビューの座標と、PDF内部の座標を同期させる処理が複雑になる可能性がある。

### Option B: `iframe`を使用したプレビュー

- **👍 Pros**
    - 実装が非常にシンプル。
    - ブラウザのネイティブPDFビューアを利用するため、安定性が高い。

- **👎 Cons**
    - インタラクティブ性が非常に低い。編集用のカスタムReactコンポーネントをPDF上に重ねて表示することができない。
    - ユーザーがPDFコンテンツを直接操作するような編集体験を提供できない。
    - メインアプリケーションと`iframe`間の通信が制限されるため、複雑な連携が困難。

### Option C: 単一ライブラリ（例: 商用ソリューション）

- **👍 Pros**
    - プレビューと操作が統一されたAPIで提供されるため、統合がシンプルになる可能性。
    - ベンダーサポートが期待できる場合がある。

- **👎 Cons**
    - 商用ライセンスの場合、高額なコストが発生。
    - 特定ベンダーへのロックインのリスク。

## Discussion

`iframe`でPDFを表示する方法は最も手軽ですが、表示されたPDFは「一枚の絵」のようになり、その上にReactコンポーネントを重ねてインタラクティブな編集機能を実装することは非常に困難です。そのため、本プロジェクトの「リッチな編集体験」という要件を満たせないと判断しました。

`react-pdf`と`pdf-lib`を組み合わせる方法は、プレビュー画面の座標とPDF内部の座標を同期させるなど、開発の複雑さは増しますが、要件である高度な編集機能を実現できる唯一の現実的な選択肢でした。

## Decision

以上の比較検討を経て、本プロジェクトのPDFプレビューと操作ライブラリとして **`react-pdf`と`pdf-lib`の組み合わせを採用する**ことを決定しました。

この決定により、インタラクティブなPDF編集体験と柔軟なPDF出力機能を実現しつつ、プロジェクトのオープンソースとしての性質とコスト効率を維持します。2つのライブラリ間の統合における課題は、開発プロセスの中で解決可能であると判断しました。

## Consequences (結果/影響)

### Positive (良い影響)
- オープンソースライブラリの採用により、ライセンスコストを大幅に削減できる。
- `pdf-lib`の低レベルな操作性により、将来的に必要となる可能性のある高度なPDF編集機能（例: ページ操作、注釈）への拡張性が高い。
- 特定ベンダーへのロックインを回避し、技術的な自由度を確保できる。

### Negative (悪い影響)
- `react-pdf`と`pdf-lib`間のデータ同期や座標変換ロジックの実装に、追加の開発工数と複雑性が伴う。
- 2つの異なるライブラリのAPIを習得する必要があるため、開発者の学習コストがやや高くなる。
- プレビューと内部データの一貫性を保つための慎重な設計とテストが不可欠となる
