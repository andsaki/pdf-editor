# ADR: ドラッグ＆ドロップおよびリサイズライブラリの選定

## Context

### 意思決定の背景、及び目的

本アプリケーションの請求書エディタ機能では、ユーザーがテキストボックスや画像などのオブジェクトをキャンバス上で直感的に移動（ドラッグ＆ドロップ）およびリサイズできる必要があります。

このインタラクティブな機能を実現するため、パフォーマンス、アクセシビリティ、そして将来の拡張性を考慮した上で、最適なライブラリを選定することを目的とします。

### References

- `react-rnd`: https://github.com/bokuweb/react-rnd
- `dnd-kit`: https://dndkit.com/

## Considered Options

- **Option A:** `react-rnd`
- **Option B:** `dnd-kit` （リサイズ機能はカスタム実装）

## Comparison Table

| Feature | Option A (`react-rnd`) | Option B (`dnd-kit`) |
| :--- | :--- | :--- |
| **主な目的** | ドラッグ＆リサイズ可能なコンポーネント | 汎用的なD&Dツールキット |
| **リサイズ機能** | ✅ 標準搭載 | ❌ 非搭載（別途実装が必要） |
| **実装の容易さ** | 高い（特定用途に特化） | 中程度（セットアップが必要） |
| **柔軟性・拡張性** | 低い（コンポーネント志向） | 高い（ツールキット志向） |
| **アクセシビリティ** | 基本的 | 高い（最優先事項として設計） |
| **メンテナンス** | 中程度 | 非常に活発 |

### Option A: `react-rnd`

- **👍 Pros**
    - **オールインワン:** ドラッグとリサイズの両機能を単体で提供します。
    - **シンプルなAPI:** `<Rnd>`コンポーネントでラップするだけで、簡単にインタラクティブな要素を作成できます。
    - **迅速な実装:** 複雑な要件がないシンプルなユースケースに最適です。

- **👎 Cons**
    - **柔軟性の低さ:** 提供されるprops以上のカスタマイズは困難です。ソート機能など、複雑なインタラクションには不向きです。
    - **アクセシビリティへの懸念:** アクセシビリティが最優先事項として設計されていません。
    - **メンテナンスの頻度:** `dnd-kit`ほど活発には開発されていません。

### Option B: `dnd-kit`

- **👍 Pros**
    - **高いカスタマイズ性:** センサーやモディファイアといった機能により、D&D体験を完全に制御できます。
    - **アクセシビリティ第一:** キーボード操作やスクリーンリーダー対応など、高いレベルのアクセシビリティを標準で提供します。
    - **活発なメンテナンス:** コミュニティが活発で、常に最新のReactのプラクティスに追従しています。
    - **高い拡張性:** 単純なドラッグ操作だけでなく、ソート可能なリストなど、幅広い機能の基盤として利用できます。

- **👎 Cons**
    - **リサイズ機能の不在:** リサイズ機能は手動で実装する必要があり、開発コストが増加します。
    - **学習コスト:** センサーやモディファイアといった独自概念の理解が必要です。
    - **記述量の増加:** `react-rnd`に比べて、初期設定に必要なコード量が多くなります。

## Discussion

`react-rnd`と`dnd-kit`の選択は、「特定用途に特化した手軽なソリューション」と「柔軟で強力なツールキット」のトレードオフと言えます。

`react-rnd`は、単純なドラッグ＆リサイズ機能を迅速に実装するのに優れています。しかし、より複雑なインタラクションや高度なアクセシビリティが求められる場面では、その限界が課題となります。

`dnd-kit`は、より堅牢で長期的な投資と言えます。リサイズ機能の自作という追加コストはかかりますが、アクセシブルで高機能なエディタを構築するための優れた基盤を提供します。グリッドへのスナップや、高度なレイヤー管理といった将来的な機能拡張を考慮すると、`dnd-kit`の拡張性は大きな利点です。

## Decision

- 単純なプロトタイプや、独立した要素を移動・リサイズするだけのツールであれば、実装速度の観点から **`react-rnd`** は実用的な選択肢です。

- しかし、本プロジェクトのような本番環境向けの、アクセシブルで機能豊富なアプリケーションを開発する場合、リサイズ機能の自作コストを考慮しても **`dnd-kit` を推奨**します。そのアクセシビリティと拡張性は、将来の開発生産性を高めるための強固な基盤となります。

## Consequences (結果/影響)

### `react-rnd` を選択した場合

- **Positive (良い影響)**
    - 中核機能の迅速な初期開発が可能になる。
- **Negative (悪い影響)**
    - 将来、より複雑なD&D機能や高度なアクセシビリティが要求された場合、コストの高いリファクタリングが必要になる可能性がある。

### `dnd-kit` を選択した場合

- **Positive (良い影響)**
    - アクセシブルで、パフォーマンスが高く、拡張性の高い基盤を構築できる。
    - 将来の機能追加が容易になる。
- **Negative (悪い影響)**
    - リサイズロジックを自前で実装する必要があるため、初期の開発時間と複雑さが増加する。
