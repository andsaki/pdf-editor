# ADR: ドラッグ＆ドロップおよびリサイズライブラリの選定

## Context

### 意思決定の背景

本アプリケーションの請求書エディタ機能では、ユーザーがテキストボックス、画像、テーブルなどのオブジェクトをキャンバス上で直感的に移動（ドラッグ＆ドロップ）およびリサイズできる必要があります。

### 目的

このインタラクティブな機能を実現するため、以下の観点から最適なライブラリを選定します：

- **実装の容易さ**: 開発速度とメンテナンス性
- **機能の完全性**: ドラッグ＆リサイズの両方をサポート
- **パフォーマンス**: リアルタイムな操作の快適性
- **アクセシビリティ**: キーボード操作やスクリーンリーダー対応
- **将来の拡張性**: 追加機能の実装難易度

### 非機能要件

本プロジェクトにおける非機能要件は以下の通りです：

#### パフォーマンス要件
- **操作の応答性**: ドラッグ・リサイズ操作は16ms以内（60FPS）でレンダリング
- **初回レンダリング**: ページロードから初回描画まで2秒以内
- **同時操作**: 10個以上のオブジェクトを配置してもスムーズに操作可能

#### ユーザビリティ要件
- **学習容易性**: 新規ユーザーが5分以内に基本操作を習得できる
- **直感性**: マウスカーソルの変化やビジュアルフィードバックにより、操作が自明であること
- **ブラウザ互換性**: Chrome、Edge、Firefox、Safari（v14+）で同等の操作感

#### 保守性要件
- **コードの可読性**: チーム内の誰でも1時間以内にコードを理解できる
- **依存関係**: メンテナンスが活発なライブラリ（月次更新があるもの）
- **デバッグ性**: ブラウザ開発者ツールで容易にデバッグ可能

#### 拡張性要件（優先度: 中）
- **将来的な機能追加**: 複数選択、グリッドスナップ、ガイドライン表示など
- **移行コスト**: 他ライブラリへの移行時、影響範囲を局所化できる設計

#### アクセシビリティ要件（優先度: 低〜中）
- **キーボード操作**: 将来的に矢印キーでの移動に対応
- **スクリーンリーダー**: 現時点では必須ではないが、将来的に考慮

### References

- [react-rnd](https://github.com/bokuweb/react-rnd)
- [dnd-kit](https://dndkit.com/)

## Considered Options

本ADRでは、以下の2つのライブラリを比較検討しました：

1. **react-rnd**: ドラッグ＆リサイズ機能を一体化したシンプルなライブラリ
2. **dnd-kit**: モダンで拡張性の高いドラッグ＆ドロップライブラリ

## Comparison Table

### 機能面の比較

| 比較項目 | react-rnd | dnd-kit |
|---------|-----------|---------|
| **リサイズ機能** | ✅ 標準搭載 | ❌ 非搭載（別途実装が必要） |
| **ドラッグ&ドロップ** | ✅ 標準搭載 | ✅ 柔軟にカスタマイズ可能 |
| **PDF/キャンバス操作** | 座標変換が直感的 | 同期処理が複雑化しやすい |
| **アクセシビリティ** | ❌ 弱い（自前実装必須） | ✅ 強い（キーボード操作やSR対応あり） |
| **将来的拡張性** | 低 | 高（複数選択・グリッドスナップ等） |

### 非機能面の比較

| 比較項目 | react-rnd | dnd-kit |
|---------|-----------|---------|
| **パフォーマンス** | ⭐⭐⭐⭐⭐ 非常に軽量 | ⭐⭐⭐⭐ 最適化されているが重め |
| **学習コスト** | ⭐⭐⭐⭐⭐ 低（APIがシンプル） | ⭐⭐ 高（概念理解が必要） |
| **保守性** | ⭐⭐⭐⭐ コードが読みやすい | ⭐⭐⭐ 抽象度が高い |
| **開発速度** | ⭐⭐⭐⭐⭐ 最速でMVP実装可能 | ⭐⭐ 初期実装に時間がかかる |
| **バンドルサイズ** | 約 20KB (gzipped) | 約 40KB (gzipped) |
| **ブラウザ互換性** | IE11+ | Modern browsers (IE非対応) |
| **メンテナンス状況** | 活発（月1-2回更新） | 非常に活発（週次更新） |

## Option A: react-rnd

### 👍 Pros（長所）

- **オールインワン**: ドラッグ＆リサイズが標準搭載で、画面上の操作はすぐに実装可能
- **低学習コスト**: APIがシンプルで、基本的な使い方はドキュメントを見ればすぐ理解できる
- **座標管理が直感的**: PDF/キャンバス上の座標系との連携が容易
- **実績**: 広く使われており、バグが少なく安定している
- **軽量**: バンドルサイズが小さい（約20KB gzipped）

### 👎 Cons（短所）

- **拡張性の制約**: 複数選択、グリッドスナップなど高度な機能の追加が困難
- **アクセシビリティ対応が弱い**: キーボード操作やスクリーンリーダー対応が標準で未対応
- **カスタマイズ性が低い**: 内部実装に手を入れにくく、細かい挙動調整が難しい

## Option B: dnd-kit

### 👍 Pros（長所）

- **高い拡張性**: センサーやモディファイアを利用した柔軟な制御が可能
- **アクセシビリティ標準対応**: キーボード操作、スクリーンリーダーサポートが組み込まれている
- **モダンな設計**: React 18+の最新機能に対応
- **将来の拡張**: 複数選択、グリッドスナップ、衝突検出などを実装しやすい

### 👎 Cons（短所）

- **リサイズ機能非搭載**: 別途自作実装が必要（開発コストが増加）
- **学習コストが高い**: センサー/モディファイアなど、独自概念の理解が必須
- **座標同期の複雑さ**: PDF内部データとの座標同期やバグ管理が複雑になりやすい
- **バンドルサイズ**: react-rndの約2倍（約40KB gzipped）

## Discussion

### 主な議論ポイント

1. **MVP開発速度 vs 将来の拡張性**
   - react-rnd: MVP開発を最速で進められる
   - dnd-kit: 将来的な機能追加に有利だが、初期開発に時間がかかる

2. **アクセシビリティの優先度**
   - 本プロジェクトは請求書エディタという業務ツールであり、アクセシビリティは重要だが最優先ではない
   - 将来的に必要になった場合、react-rndでも独自実装で対応可能

3. **リサイズ機能の重要性**
   - 請求書のレイアウト調整において、リサイズは必須機能
   - dnd-kitでは自作実装が必要で、開発リスクが高い

## Decision

**react-rnd を採用する**

### 選定理由

1. **MVP開発の優先**: 初期開発速度を重視し、基本機能を早期にリリースする
2. **リサイズ機能の標準搭載**: 自作実装のリスクを回避
3. **学習コストの低さ**: チームメンバーが短期間で習得可能
4. **実装の安定性**: 本番環境での実績が豊富

### 実装方針

- `PdfPreview.tsx` で各レイアウトアイテムを `<Rnd>` でラップ
- `onDragStop` と `onResizeStop` イベントで座標・サイズを更新
- zIndexによる重なり順の制御

## Consequences

### ポジティブな影響

✅ **開発速度の向上**: 基本機能を短期間で実装完了
✅ **安定性**: バグが少なく、本番運用のリスクが低い
✅ **メンテナンス性**: シンプルなAPIで、コードが読みやすい

### ネガティブな影響・懸念事項

⚠️ **アクセシビリティ対応**: キーボード操作は将来的に独自実装が必要
⚠️ **高度な機能の追加**: 複数選択、グリッドスナップなどは実装コストが高い
⚠️ **移行コスト**: 将来dnd-kitに移行する場合、大規模なリファクタリングが必要

### 緩和策

- **アクセシビリティ対応**: 要件が明確になった時点で、段階的に独自実装を追加
  - 矢印キーによる移動（例: 1px / 10px単位）
  - Tab/Shift+Tabによるフォーカス移動
  - aria-label等の追加

- **高度な機能が必要になった場合の対応**: 以下の機能が求められた際は、dnd-kitへの移行を再検討
  - **複数選択**: Shift/Ctrlキーで複数オブジェクトを同時選択し、一括移動・削除
  - **グリッドスナップ**: オブジェクトを5px/10pxのグリッドに自動吸着
  - **ガイドライン表示**: 他のオブジェクトと整列時にガイドラインを表示
  - **衝突検出**: オブジェクト同士の重なりを防止・警告
  - **ドラッグプレビュー**: ドラッグ中のオブジェクトのゴースト表示
  - **オブジェクトグループ化**: 複数オブジェクトをグループとして扱う
  - **回転機能**: オブジェクトを任意の角度で回転
  - **レイヤー間のドラッグ**: 異なるキャンバス間でのオブジェクト移動

- **現時点の方針**: MVPに集中し、ユーザーフィードバックから真に必要な機能を特定

### 将来の移行シナリオ

もしdnd-kitへの移行が必要になった場合：

1. **段階的移行**: 新機能のみdnd-kitで実装し、既存機能は react-rnd のまま維持
2. **ハイブリッド構成**: 基本操作はreact-rnd、高度な操作はdnd-kitと併用
3. **全面移行**: ユーザー数が増え、ROIが見込める場合のみ検討（推定工数: 2-3週間）
