# ADR: フロントエンドフレームワークの選定

## Context

### 意思決定の背景、及び目的

モダンなWebアプリケーションを構築するにあたり、将来の拡張性、保守性、開発者体験を考慮したフロントエンドフレームワークの選定が不可欠です。

このADRでは、業界で広く採用されている2大フレームワークであるReact（およびそのメタフレームワークNext.js）とVue（およびそのメタフレームワークNuxt.js）を比較検討し、技術選定のための判断材料を提供することを目的とします。

### References

- React: https://react.dev/
- Next.js: https://nextjs.org/
- Vue: https://vuejs.org/
- Nuxt.js: https://nuxt.com/

## Considered Options

- **Option A:** React (with Next.js)
- **Option B:** Vue (with Nuxt.js)

## Comparison Table

| Feature | Option A (React + Next.js) | Option B (Vue + Nuxt.js) |
| :--- | :--- | :--- |
| **基本概念** | UIを構築するためのライブラリ | プログレッシブフレームワーク |
| **メタフレームワーク** | Next.js | Nuxt.js |
| **テンプレート** | JSX (JavaScript内にHTMLを記述) | SFC (.vue) / HTMLベースのテンプレート |
| **TypeScriptとの相性** | **非常に良い**。JSXの型サポート（.tsx）は成熟しており、エコシステム全体で強力な型定義が提供される。 | **非常に良い**。Vue 3はTypeScriptで書き直されており、特にComposition APIは優れた型推論を提供する。 |
| **学習コスト** | やや高い（JSX、状態管理など選択肢が多い） | 比較的低い（HTML/CSS/JSに近い） |
| **エコシステム** | 最大規模。膨大なライブラリが存在。 | 巨大かつ、公式ライブラリとの統合性が高い。 |
| **柔軟性** | 非常に高い（多くの技術選定を自分で行う） | ある程度規約があり、柔軟性も高い |
| **コミュニティ/求人**| 市場で最大のシェアを持つ | 非常に大きい。特にアジア圏で人気。 |
| **状態管理** | Redux, Zustandなど多くの選択肢 | Pinia (公式), Vuex |

### Option A: React (with Next.js)

- **👍 Pros**
    - **最大のエコシステム:** ライブラリ、ツール、学習教材が豊富で、ほぼ全てのユースケースに対応可能です。
    - **成熟したTypeScriptサポート:** Next.jsを始め、エコシステムの多くがTypeScriptを前提に作られており、大規模開発でも堅牢な型システムの恩恵を受けられます。
    - **豊富な人材:** React開発者の数が多く、人材確保が比較的容易です。
    - **高い柔軟性:** プロジェクトの要件に合わせて、状態管理やスタイリングなどの技術を自由に組み合わせることができます。
    - **強力な支援:** Meta社による強力なバックアップがあります。

- **👎 Cons**
    - **決定疲れ:** 自由度が高い反面、多くの技術選定を開発チーム自身が行う必要があり、「決定疲れ」を引き起こす可能性があります。
    - **JSXの壁:** 従来のWeb開発者にとって、JavaScript内にHTMLを記述するJSXは学習の障壁となることがあります。
    - **エコシステムの断片化:** 多くの選択肢があるため、ライブラリ間の相性問題などが発生する可能性があります。

### Option B: Vue (with Nuxt.js)

- **👍 Pros**
    - **低い学習コスト:** 単一ファイルコンポーネント（SFC）は直感的で、HTML/CSS/JSの知識を活かしやすいです。
    - **第一級のTypeScriptサポート:** Vue 3はTypeScriptで書き直されており、Composition APIと組み合わせることで、propsやemits、状態管理において優れた型推論の恩恵を受けられます。
    - **優れたドキュメント:** 公式ドキュメントが非常に分かりやすく、整備されています。
    - **統合された開発体験:** Nuxt.jsはルーティング、状態管理、SSRなどを規約ベースで提供するため、迅速な開発と一貫性のある設計が可能です。
    - **公式ライブラリ:** ルーターや状態管理ライブラリが公式でメンテナンスされており、エコシステム全体の一貫性が高いです。
    - **充実したエコシステム:** PDF編集のような特定の要件に対しても、Reactエコシステム（例: react-pdf, dnd-kit）に相当する代替ライブラリ（例: VuePDF, @vueuse/gesture, vue-draggable-resizable）が十分に存在し、同等の機能実装が可能です。

- **👎 Cons**
    - **エコシステムの絶対数:** Reactに比べるとライブラリの絶対数は少なく、非常にニッチな要件の場合には代替ライブラリの調査が必要になることがあります。
    - **人材市場:** 地域によっては、React開発者に比べてVue開発者の人材プールが小さい場合があります。
    - **企業の後ろ盾:** Reactほどの巨大企業による後ろ盾はありませんが、非常に強力なオープンソースコミュニティによって支えられています。

### 主要ライブラリの比較 (React vs Vue)

本プロジェクトで必要となる主要な機能（PDF操作、Drag and Drop）について、ReactとVueのエコシステムにおける代表的なライブラリを比較検討します。

| 機能 | Reactライブラリ | Vueでの代替候補 | 主な特徴 |
| :--- | :--- | :--- | :--- |
| **PDF表示** | `react-pdf` | **`vue-pdf-embed`** | シンプルなPDFビューアとして簡単に導入できる。 |
| **PDF生成** | `react-pdf` | **`jsPDF`**, **`pdf-lib`** | 高機能で柔軟なPDFの動的生成が可能。 |
| **D&D (リスト並べ替え)** | `dnd-kit` | **`VueDraggableNext`** | 最も多機能で安定している。リスト操作に強い。 |
| **D&D (要素の移動)** | `dnd-kit` | **`@vueuse/core` の `useDraggable`** | Composition APIベースで軽量。シンプルな移動に適している。 |

迅速なプロトタイピングが求められる状況において、Vueを選択した場合でも、成熟し安定した代替ライブラリが存在することは、技術選定におけるリスクを低減させます。

### 最新市場トレンド (State of JS 2024より)

近年の技術トレンドを反映するため、"State of JS 2024"のデータを考慮します。
https://2024.stateofjs.com/ja-JP/libraries/front-end-frameworks/

*   **React**: 使用率において82%と圧倒的な首位を維持しており、市場での普及率とエコシステムの巨大さを裏付けています。一方で、その複雑性などから不満の声も上がっている点が注目されます。
*   **Vue**: 使用率51%で2位を維持しつつ、定着率（一度使った開発者が使い続けたいと思う割合）が向上しています。これは、開発者体験（DX）や学習のしやすさといった点で高い満足度を得ていることを示唆します。

このデータは、Reactが市場での「安定性と普及率」に優れ、Vueが「開発者の満足度と生産性」に優れるという、これまでの定性的な評価を裏付けるものです。

## Discussion

Reactの強みは、その圧倒的な柔軟性と巨大なエコシステムにあります。独自の要件を持つ大規模プロジェクトや、特定のライブラリが必要な場合、Reactは強力な選択肢となります。Next.jsはその上で堅牢な基盤を提供し、Reactの「自由すぎる」という側面を補完します。

一方、Vueの強みは、その学習のしやすさと、まとまりのあるエコシステムにあります。Nuxt.jsは「バッテリー同梱」の開発体験を提供し、チームのスキルセットに関わらず、迅速で一貫した開発を促進します。特に開発者体験（DX）の高さで評価されています。

どちらを選択するかは、チームの既存の専門知識、プロジェクトの要要件、そして長期的な目標に依存します。かつてはTypeScriptとの相性も比較の論点でしたが、現在では両者とも第一級のサポートを提供しており、決定的な差別化要因にはなりにくくなっています。

## Decision

**プロジェクトの状況に応じて選択する。**

- **React (Next.js)が適しているケース:**
    - チームがReactに精通している。
    - 非常に特殊な要件があり、Reactエコシステムにしか存在しないライブラリが必要。
    - 開発者の人材確保を最優先したい。

- **Vue (Nuxt.js)が適しているケース:**
    - 迅速なプロトタイピングと開発が求められる。
    - チームメンバーのスキルレベルにばらつきがある。
    - 一貫性のある開発体験と、学習コストの低さを重視する。

現在の「invoice-editor」プロジェクトではReactが採用されていますが、これはチームの習熟度や、PDF操作など特定のライブラリ（`react-pdf`など）との親和性を考慮した結果であると考えられます。

## Consequences (結果/影響)

この決定は、どちらかの技術を選択した場合に起こりうる結果を記述します。

### React (Next.js) を選択した場合

- **Positive (良い影響)**
    - 豊富なライブラリを活用し、複雑な要件にも対応しやすい。
    - 世界標準とも言える技術スタックにより、開発者の採用や情報収集が容易になる。
- **Negative (悪い影響)**
    - 多くの技術選定が必要となり、アーキテクチャが複雑化する可能性がある。
    - チーム内でのコーディング規約や設計思想の統一がより重要になる。

### Vue (Nuxt.js) を選択した場合

- **Positive (良い影響)**
    - Nuxt.jsの規約に従うことで、開発の初期段階で迅速に立ち上がることができる。
    - フレームワークに多くの機能が統合されているため、開発者体験が向上し、生産性が高まる。
- **Negative (悪い影響)**
    - Reactエコシステムに存在するニッチなライブラリが必要になった場合、代替手段を探すコストが発生する可能性がある。
    - フレームワークの規約が、プロジェクトの特殊な要件と合わない場合に制約となる可能性がある。
